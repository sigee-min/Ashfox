# Intent Program 1

Intent Program 1 is a closed, coordinate-free asset language written by an AI
agent from a human prompt. A `.ashfox` file contains only this source. The
compiled project, geometry, materials, texture raster, rig, and animation are
disposable projections.

## Authority blocks

Every complete source contains exactly one block of each kind. Block order has
no semantic effect.

| Block | Sole authority |
| --- | --- |
| `metadata` | Asset name, quality track, and subject domain. It is closed metadata, not a free-form key/value bag. |
| `model` | Orientation, symmetry, support contacts, topology, spatial attachment, morphology, surfaces, face, and focal meaning. |
| `animation` | Coordinate-free motion intent. It never exposes keyframes or transforms. |
| `appearance` | Palette, material character, deterministic seed, semantic regions, and local motif placement. |

Root declarations and declarations placed in the wrong owner block are errors.
There is no second `style`, `motion`, or geometry authority.
Only the current language version is accepted. Breaking grammar changes require
a language-version change; they do not add aliases or a compatibility parser.

## Orthogonal relationships

A body or surface relationship uses independent typed fields:

- `parent` names only the topology parent;
- `anchor` names only a closed spatial port on that parent;
- `growth` names only the morphology axis away from the anchor;
- `lane` selects a closed sub-port when siblings share an anchor;
- the declaration ID is an opaque semantic-region handle and is never parsed
  for anatomy or placement.

`parent` therefore cannot silently choose a position, and an anchor cannot
silently change graph ownership. The constraint resolver validates every
parent/anchor/growth/lane combination before geometry exists.

Support is declared as contact semantics: `support none`, or a typed support
kind with explicit `contacts`. It is not an airborne pose or animation state.
`forward` belongs to the project orientation or a growth axis; `front` belongs
to an anchor. `transverse` is an axis, while an appearance `region` is semantic
surface meaning.

Appearance markings likewise keep independent roles:

- `target` selects a named semantic owner;
- `region` selects a closed region of that owner;
- `placement` selects a motif-local placement inside the region;
- `flow` is accepted only by motifs whose schema declares it.

## Typed statement schemas

No statement accepts an open property bag. Each statement kind has one closed
schema in the language specification: required fields, optional fields, value
types, multiplicity, and compatibility rules. Unknown, missing, duplicate, and
wrong-owner fields are reported together at their exact source spans.
The workbench Agent manifest publishes a JSON-safe projection of this same
specification; it does not maintain a second grammar table.

A surface shape is a nested typed statement. Its `axis`, `span`, `chord`,
`tip`, `offset`, and `edge` fields are each required exactly once and may appear
in any order. Adding a future field requires a specification change, reader
support, constraint policy, canonical projection, and capability test; it
cannot be smuggled through a generic map.

## Compiler stages

~~~text
UTF-8 Intent Program source
  -> lexer and closed block reader
  -> immutable Semantic AST
  -> constraint resolution
  -> canonical coordinate-free Model IR
  -> geometry, material, texture, rig, and animation generation
  -> canonical validation and receipt
~~~

The reader imports no modeling, raster, scene, or exporter code. Constraint
resolution owns references, cycles, attachment compatibility, support targets,
surface-shape compatibility, capacity, and diagnostic ordering. Generation
consumes only the resolved Model IR and must not reread source declarations or
infer meaning from IDs.

Canonical ordering is independent of root-block order and sibling-statement
declaration order. Properties in explicitly unordered blocks such as `face`
and `shape` may also be reordered. Positional statement clauses remain strict:
their schema-defined token order is part of the closed language and is not an
open property bag. Equivalent accepted source therefore resolves to the same
Model IR and generated bytes. Failed resolution never creates a partial
project.

## Deliberate abstraction boundary

Intent Program declares what the asset is: topology, morphology, support,
semantic regions, surface character, and motion intent. It never exposes
vertices, faces, cubes, lattice coordinates, pivots, UVs, shaders, materials,
or keyframes. New capabilities must extend the semantic vocabulary and typed
constraints rather than puncture this boundary with low-level editing.
