# Surface Appearance V1

Surface Appearance V1 turns coordinate-free appearance intent into a
deterministic generated raster. It is not a choice between a flat color and a
face-wide light/dark split. Its visual target is:

> a dominant color family with rich, low-contrast surface variation and a
> small number of semantically placed local contrasts

## Implementation status

Intent Program 1 implements the complete Surface Appearance V1 path: a closed
source block, normalized coordinate-free appearance intent, compiler-owned
semantic target bindings, object-space deterministic material and marking
masks, base-dominant tone budgets, protected focal regions, palette
projection, `surfaceSynthesisVersion: 1` metadata validation, and canonical
generated-RGBA receipt binding.

Every Intent Program 1 source owns exactly one `appearance` block. It must
contain exactly one palette, one complete texture declaration, and one seed
declaration; markings remain optional. Omitted blocks, hidden domain defaults,
partial declarations, and opt-outs such as `appearance none` are invalid.

The AI authors appearance as part of Intent Program 1. A human describes the
desired look in chat and observes the compiled result; the workbench does not
expose UV painting, procedural-noise controls, or a derived texture editor.

## Authorities

The authorities are deliberately separate:

| Decision | Authority |
| --- | --- |
| Available appearance words and capabilities | Intent Program 1 appearance specification |
| Normalized authored appearance meaning | immutable `IntentProgramAppearance` intent |
| Part, semantic-region, placement, and project-frame resolution | compiler appearance planner |
| Automatic texel role mask | Surface Synthesis 1 |
| RGB colors for roles | compiler-owned palette |
| Final generated bytes | canonical raster compositor |
| Generated appearance reproducibility | compilation receipt and raster digest |

A palette never decides where a mark appears. A seed never decides geometry,
hierarchy, support, motion, or feature meaning. Atlas placement, node order,
project revision, timestamps, and runtime randomness are never appearance
inputs.

## Source language

The required owner block is closed. Its accepted source form is:

~~~text
appearance {
  palette ocean
  texture mottle scale broad density balanced contrast subtle
  seed reef-17
  mark pale-belly target body torso region ventral placement whole as wash tone lighter scale broad density sparse contrast subtle
  mark gills target body head region posterior-flank placement center as bars tone darker flow vertical scale fine density sparse contrast medium
}
~~~

`seed auto` is an explicit declaration, never an implicit default. An explicit
lower-kebab seed makes a variation portable between equivalent assets. A
mark's stable ID creates an independent seed stream. An optional
`variant <lower-kebab>` changes only that mark without renaming its semantic
identity.

Each statement has one closed schema and fixed order:

~~~text
palette <palette>
texture <kind> scale <scale> density <density> contrast <contrast>
seed auto|<lower-kebab>
mark <id> target <kind> [target-id] region <region> placement <placement>
  as <motif> tone <tone> [flow <flow>] [variant <lower-kebab>]
  scale <scale> density <density> contrast <contrast>
~~~

`face` is the only target kind without a target ID. Only `band`, `stripe`, and
`bars` accept `flow`; every other motif requires that field to be absent. The
reader rejects unknown fields, reordered clauses, aliases, and partial lines.
The deep-frozen `PROJECT_APPEARANCE_SPECIFICATION.statements` descriptors are
the executable authority for statement cardinality, field order, vocabulary
references, target-ID cardinality, and motif-flow conditions.

Closed vocabularies:

- texture: `quiet`, `mottle`, `grain`, `brushed`, `weathered`;
- target namespace: `body`, `surface`, `face`, `focal`;
- region: `full`, `dorsal`, `ventral`, `flank`, `anterior`, `posterior`,
  `dorsal-flank`, `ventral-flank`, `anterior-flank`,
  `posterior-flank`;
- placement: `whole`, `center`, `root`, `tip`, `joint`, `edge`;
- motif: `wash`, `band`, `stripe`, `bars`, `spots`, `patch`, `rim`;
- tone: `lighter`, `darker`, `accent`;
- flow: `longitudinal`, `vertical`, `transverse`, `radial`;
- scale: `fine`, `medium`, `broad`;
- density: `sparse`, `balanced`, `rich`;
- contrast: `subtle`, `medium`, `bold`.

The language does not accept RGB values, opacity, UV coordinates, face IDs,
noise octaves, frequencies, thresholds, or arbitrary shader code. Those are
compiler details, not appearance meaning.

## Normalized appearance IR

Normalization produces an immutable, coordinate-free contract equivalent to:

~~~text
IntentProgramAppearance {
  version: 1
  palette: natural | ember | ocean | noir | metal | gold
  seed: auto | explicit(value)
  texture: { kind, scale, density, contrast }
  markings: [
    { id, target: { kind, id? }, region, placement, motif, tone, flow?, scale,
      density, contrast, variant? }
  ]
}
~~~

Markings are sorted by stable ID. Targets resolve against declared body and
supported-surface IDs before lowering. The compiler reports duplicate IDs,
unknown targets, invalid target-region or target-placement combinations,
motif-flow mismatches, and
ambiguous overlaps at their source tokens. It returns all diagnostics in
source order.

There are no authored appearance defaults. The source must select palette,
texture character, texture controls, and seed explicitly. An empty marking
list means no semantic marks; compiler-owned focal and component budgets still
apply to the declared material field.

## Activation pipeline

~~~text
appearance source
  -> closed reader and source map
  -> normalized IntentProgramAppearance
  -> semantic target, region, and placement planner
  -> object-space appearance plan
  -> deterministic role-mask synthesis
  -> palette role projection in OKLab
  -> feature motifs such as eyes and mouths
  -> canonical raw RGBA raster
  -> raster digest and export encoding
~~~

### 1. Project and part frames

The planner derives a project frame from the declared forward direction,
world up, and bilateral axis. Each target receives normalized forward,
vertical, and transverse ranges plus attachment-root and tip information.
Regions and placements are evaluated in that frame, not inferred from IDs and
not reconstructed from atlas UVs.

Examples:

- `dorsal` selects the upper region in the project frame;
- `ventral` selects the lower region;
- `root`, `tip`, and `joint` placements use the compiler-owned attachment axis;
- `posterior-flank` intersects posterior and flank masks;
- paired targets share a mirrored semantic mask while retaining independent
  low-contrast micro-variation.

### 2. Three appearance layers

The compositor owns three non-overlapping concerns.

1. **Material field** — low-contrast object-space variation inside the main
   color family. It uses compact multi-scale clusters, never a rectangle-wide
   linear light gradient.
2. **Semantic markings** — authored washes, bands, bars, spots, patches, and
   rims clipped to typed target regions and placements. These provide the meaningful local
   contrast.
3. **Feature motifs** — eyes, pupils, nose, mouth, signs, and other focal
   glyphs. These paint last and own a protected halo so background variation
   cannot make them unreadable.

Face-normal lightness remains a small, globally consistent material cue. It is
not reused as a local pattern and therefore cannot produce a yin-yang split.

### 3. Deterministic material field

Surface Synthesis 1 samples integer object-space coordinates with stable hash
streams. The texture kind changes the topology of compact clusters:

- `quiet` keeps nearly all texels at the base tone;
- `mottle` creates rounded low-frequency clusters;
- `grain` creates fine, sparse variation;
- `brushed` elongates clusters along the part's semantic axis;
- `weathered` biases small clusters toward exposed edges and tips.

Scale changes correlation distance, density changes the exact texel budget,
and contrast changes only OKLab distance. Contrast never changes the role
mask. Palette changes only RGB projection. The implementation uses integer or
fixed-point decisions so accepted input is byte-stable across hosts.

Hard distribution limits:

- components of four texels or fewer are entirely base tone;
- components of five to seven texels contain at most one varied texel;
- components of eight to fifteen texels contain at most two varied texels;
- regular large components retain at least 70% base tone, with a target range
  of 78-84%;
- focal large components retain at least 80% base tone, with a target range of
  86-90%;
- no connected varied cluster exceeds 20% of the occupied component;
- no varied cluster bridges opposite component boundaries.

These are topology invariants, not screenshots or tuning suggestions.

### 4. Semantic marking masks

Motifs are analytic masks perturbed by the mark's deterministic seed stream:

- `wash` is one broad region-weighted color shift with an irregular boundary;
- `band` crosses a target once along its semantic axis;
- `stripe` is one elongated, gently varying line;
- `bars` is a small bounded set of parallel short stripes;
- `spots` is a bounded set of compact islands;
- `patch` is one compact island;
- `rim` follows a selected semantic boundary.

The compiler derives motif count and thickness from closed scale and density
values. It does not expose procedural parameters. Marks compose in a fixed
class order: wash, band, stripe/bars, spots/patch/rim, then focal features.
Overlaps that would make same-class ordering observable are rejected instead
of depending on source or object iteration order.

## Seed contract

Surface Synthesis 1 derives its automatic seed from canonical semantic inputs
and supports two source modes:

- explicit: hash `SurfaceAppearanceV1 | explicit value`;
- auto: hash a canonical appearance-seed projection of geometry semantics,
  target relationships, and mask-producing appearance controls.

The auto projection excludes asset display name, palette, tone color role,
contrast, project ID, revision, timestamps, generated node IDs, atlas layout,
and export target. Therefore:

- changing `palette ocean` to `palette ember` preserves every role mask;
- changing only contrast preserves every role mask;
- changing only the seed preserves geometry and semantic markings but produces
  a different deterministic variation;
- changing a mark's variant changes only that mark;
- repacking the atlas preserves every world-surface texel.

Seed streams are derived by stable semantic path, never consumed from a shared
stateful random sequence. Reordering declarations or scene nodes cannot move
randomness between parts.

## Provenance and versioning

`surfaceSynthesisVersion: 1` is stored and validated. The compilation receipt
includes a canonical generated-raster projection, so the current automatic
synthesis binds texture metadata and raw RGBA bytes. The normalized authored
appearance IR is part of project intent and therefore the output digest. The
complete projection contains:

- normalized appearance IR;
- Surface Synthesis version;
- texture ID, dimensions, sampling, color space, and render mode;
- canonical raw RGBA bytes in stable texture-ID order.

Intent Program remains version 1. Surface Appearance and Surface Synthesis
each keep their own version `1`. PNG encoder output is a delivery concern; the
canonical raster digest uses raw RGBA so browser or encoder metadata cannot
create false drift. Once Surface
Synthesis 1 is frozen, changing its raster bytes requires a new synthesis
version or an explicit migration. Representative golden raster digests make
an accidental same-version visual change fail CI.

## Required verification

The verification matrix covers base dominance, deterministic seeds,
palette/contrast mask independence, fragmentation and atlas invariance, focal
protection, topology bounds, semantic target realization, source diagnostics,
and representative raster regressions:

- palette independence: identical role masks, different RGB;
- contrast independence: identical role masks, different OKLab distances;
- explicit and auto seed determinism;
- atlas, cube partition, scene-order, and declaration-order invariance;
- project-frame rotation and bilateral reflection behavior;
- small, irregular, focal, support, radial, and supported-surface components;
- cluster-size and opposite-boundary invariants across many seeds;
- focal glyph and protected-halo precedence;
- authored dorsal wash, ventral band, flank bars, tip patch, and edge rim;
- exact source-span diagnostics for every invalid combination;
- raw raster golden digests for representative organism and constructed
  assets.

The Agent may summarize the compiled meaning as, for example, “subtle broad
mottling, pale belly, three dark rear flank bars, seed reef-17.” Technical seed
and digest details remain available to the Agent and receipts; the human-facing
workbench remains an observation, capture, and delivery surface.
